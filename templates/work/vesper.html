Vesper — Local-First Personal Workspace

A local-first personal workspace built on Flask + SQLite. Features instant autosave, inline block editing, command palette navigation, and zero cloud dependencies.

Executive Summary Local-First Workspace
Problem

SaaS Note Bloat: Modern knowledge management platforms impose login walls, subscription tiers, and heavy cloud synchronization on users who just need instantaneous, distraction-free local capture.

Decision

Zero-Auth Local Persistence: Built a lightweight Flask + SQLite application prioritizing keyboard velocity: inline contenteditable blocks, global command palette (Ctrl+K), and responsive sidebar navigation.

Evidence

Functional Workspace Prototype: Working local web app (launch prototype) with full hierarchical page management, real-time autosave indicators, and instant local search.

Boundary

Solo Personal Use: Strictly a single-user local tool. Has no cloud backup, no multi-user access controls, and no production SaaS user research.

Context

Vesper is a personal workspace application — a place to keep notes, drafts, writing, and references in a structured way. It was built as a Flask + SQLite web application that runs locally, with no authentication and no multi-user features. The goal was to create a focused editing environment with good keyboard support and fast feedback.

The product is local-first by design: everything lives in a SQLite database on the local machine, and there is no network dependency. The interface is built around a sidebar of pages and an inline block editor where each block is a contenteditable element.

Problem / Motivation

Proposed

The motivation below is a product decision. It is not validated with users.

Many note-taking tools are either too simple (a single text file or a bare list) or too complex (enterprise wikis with permissions, sync, and collaboration features the individual user does not need). Vesper sits in the middle: structured enough to organize work into pages and blocks, simple enough to stay focused on editing.

The hypothesis is that a local-first tool with contenteditable blocks, a command palette, and autosave can feel fast and focused for personal writing and note-taking — without the overhead of sync, accounts, or collaboration features. This is a product hypothesis, not a validated finding.

Product Decision

Proposed

The decisions below are product choices. They are not validated with users.

Stack decision

Flask + SQLite + Jinja2. Server-rendered templates with a lightweight AJAX layer for block CRUD, autosave, favorites, and reordering. No frontend framework. No build step. This keeps the application simple and portable — a single database file, a single Python process.

Local-first, no authentication

Vesper is designed for a single user on a local machine. There is no authentication, no multi-user support, and no network dependency. The trade-off: no sync across devices, no sharing, no collaboration. The benefit: zero backend complexity, instant loading, and a single SQLite file as the entire data store.

Contenteditable blocks

Each page is made of blocks — heading1, heading2, heading3, paragraph, bullet, check, code, divider. Blocks are contenteditable, so the user edits inline rather than in a separate form. New blocks can be added by clicking the + button that appears on hover, or by pressing Enter in an existing block. This is the core editing model.

Command palette

Ctrl/Cmd+K opens a command palette that searches pages by title and content. The palette is a server-side search API backed by SQLite FTS-like substring matching. This gives keyboard-driven page navigation without requiring the mouse.

How It Works

Vesper's interface has two main areas: a sidebar listing pages, and an editor area showing the selected page's blocks. The sidebar shows page titles, block counts, last-updated dates, and a star for favorites. Pages can be reordered by dragging, favorited with a click, and deleted with a confirmation.

The editor area shows blocks stacked vertically. Each block is a contenteditable div with a block-type label. Hovering over a block reveals a + button to add a new block below. Pressing Enter in a block creates a new paragraph block below. Autosave sends block content to the server on a debounced interval, with visual "Saving…" and "Saved" feedback.

Key / Action What it does
Ctrl/Cmd + K Open command palette — search pages by title or content
Enter in a block Create a new paragraph block below the current one
Hover + click + Add a new block below the hovered block
Star in sidebar Toggle favorite — favorites appear at top of sidebar
Drag in sidebar Reorder pages

Evidence Limits

What Vesper demonstrates

  • A working Flask + SQLite web application with full CRUD
  • Contenteditable block editing with autosave
  • Command palette with server-side page search
  • Sidebar with favorites, reordering, delete
  • Responsive layout with sidebar collapse on narrow screens
  • Visual autosave feedback ("Saving…" / "Saved")

What Vesper does not claim

  • User research or usability testing
  • Validated demand
  • Adoption or usage data
  • Multi-user or collaboration features
  • Sync across devices
  • Production deployment with real users

What I Would Validate Next

Proposed

The validation steps below are proposed. None have been done for Vesper.

  1. Editing efficiency. Measure whether contenteditable block editing is faster or more fluid than a traditional form-based editor for the same writing tasks.
  2. Command palette usefulness. Test whether keyboard-driven page search via Ctrl+K is actually used and preferred over sidebar navigation.
  3. Autosave trust. Verify that the autosave feedback is clear enough that the user trusts their content is saved without manual action.
  4. Block type discoverability. Check whether users understand the available block types and use them appropriately, or whether the palette of types is confusing.
Not evidenced

None of the above has been done. Vesper is a working prototype. It is not a validated product.
