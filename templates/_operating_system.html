How I Work

A repeatable process — backed by real evidence.

This isn't a generic product methodology. Each stage is anchored to something I've actually done. The thread is the same across all three projects: define, measure, verify, and be honest about the gaps.

D

Discover

Identify meaningful problems. Frame them with user segments and JTBD hypotheses. Label assumptions explicitly.

Evidence: Unrot D1 retention problem framing + JTBD hypotheses · ReviewFlow AI product principle · Experiment Tracker experiment→decision gap

Df

Define

Turn ambiguous problems into defined products with clear boundaries, user needs, and success criteria.

Evidence: Experiment Tracker PRODUCT_BRIEF · ReviewFlow product decisions + MVP prioritization + architecture doc · Unrot measurement model + D1 retention model

De

Decide

Prioritize alternatives with explicit criteria. Make trade-offs with rationale. Choose the smallest capability that addresses the most important gap.

Evidence: Experiment Tracker 7-candidate prioritization with "why not prioritized" · ReviewFlow guardrail decisions · Unrot measurement model over feature breadth

B

Build

Build working products — or work closely with engineering — across multiple stacks, with verification in mind.

Evidence: ReviewFlow (React + Supabase + TypeScript) · Unrot (Next.js + PostgreSQL + Prisma) · Experiment Tracker (Flask + SQLite + Jinja2, 22 tests)

M

Measure

Define success metrics. Build measurement systems. Design experiments to test hypotheses.

Evidence: ReviewFlow AI quality measurement (247 checks, output evaluator, 15 cases, intervention record) · Unrot measurement model (metric hierarchy, funnel, instrumentation) · Experiment Tracker proposed usage metric

V

Verify & Learn

Use evidence to make decisions. Verify what you claim. Be honest about what you haven't validated. Feed evidence back into the next decision.

Evidence: ReviewFlow failure analysis + intervention record (honest, not validated) · Unrot analytics design + honest "not enough data yet" state · Experiment Tracker 17-category verification report · KAIRO Verification Truthfulness Protocol

How I work — the system behind this

I use a product-engineering methodology called KAIRO — a structured approach to product work that emphasizes evidence discipline, verification truthfulness, and AI-assisted product development. It's the system that encodes the evidence-label discipline you see across this portfolio.

KAIRO is an operator note, not a shipped product. It has no application code, no users, no outcomes, no measurement. It's the methodology I use — and the standard this portfolio holds itself to.
